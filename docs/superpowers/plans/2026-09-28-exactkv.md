# ExactKV Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Determine whether native Q4 plus exact BF16 interval refinement provides a useful measured inference trade-off, delivering executable evidence or a justified early no-go.

**Architecture:** Keep native Q4 prompt storage unchanged, add a CPU-packed exact conditional stream, and reconstruct only one verifier layer at a time. Reuse one model and stock attention with bounded exact tails. Gates compare against independent exact compression and stop dependent work when evidence fails.

**Tech Stack:** ARM-native Python 3.12, NumPy, MLX, MLX-LM, pytest, huggingface_hub, zstandard, and small Python-defined Metal kernels.

**Spec:** [ExactKV design](../specs/2026-09-28-exactkv-design.md). Read it together with [source notes](../../research/2026-09-28-source-audit.md); neither this plan nor the source ledger certifies G0 or any experimental result.

## Global Constraints

- Platform: one local Apple M3 Max; batch size 1.
- Environment: ARM-native Python 3.12 or a demonstrated compatible existing ARM-native environment.
- Dependencies: Python, NumPy, MLX, MLX-LM, pytest, huggingface_hub, zstandard; datasets only if its loader is used.
- Model: official `Qwen/Qwen3-0.6B`, original BF16 weights, immutable model/tokenizer revision, no training or weight modification.
- Geometry: verify 28 layers, 16 query heads, 8 KV heads, head dimension 128 at runtime.
- Context: prompt plus every actually processed candidate block stays within 32,768 positions.
- Approximate view: native MLX affine Q4, group size 64, original codes/scales/biases unchanged.
- Exact source: original BF16 post-RoPE K and actual V as consumed by attention.
- History: immutable compressed prompt; at most 256 emitted output tokens; authoritative BF16 generated tail.
- Verification: deterministic greedy, non-thinking template, initial draft horizon 4; development ablations only at 2, 4, 8.
- Staging: one layer of exact K/V, with at most one additional layer-sized assembly buffer, measured and charged.
- Implementation order: CPU reference and evidence gates before any custom Metal reconstruction.
- Excluded: stochastic sampling, batching, eviction, networking, offload memory claims, persistent sessions, prefix sharing, tensor parallelism, sliding windows, training, GPU variable-output packing, rANS, a dynamic allocator, custom attention.
- No CUDA, PyTorch, distributed serving framework, Docker, or experiment-tracking service dependency.

Keep the requested current branch; do not make a worktree or nested repository. The present deliverable is documentation only. All checkboxes below are future implementation work. Do not mark them complete from planning observations, and do not run future commands merely because this file lists them.

## Review Focus

- Missing telemetry under a restricted shell must remain unavailable with a reason; it must not turn into zero swap or unlimited available memory. Task 1 tests this.
- Mutable source aliases, tokenizer changes, and interrupted manifest writes must not silently change an experiment or pass as a pinned run. Tasks 3–4 test this.
- A valid-looking refinement stream bound to altered Q/scales or another head must fail before GPU use. Task 10 tests this.
- Draft EOS, accepted EOS, one-output limits, and the last legal position must not over-emit or commit rejected KV. Tasks 8 and 14 test this.
- Small views, queued lazy computations, and interrupted construction must not keep previous layers or sessions alive. Tasks 13–14 test this.

### Shared interface vocabulary

Task 1 defines `JsonDict = dict[str, Any]`, a schema-versioned JSON record validated by `records.validate_record(kind: str, record: JsonDict) -> None`, and `write_record(path: Path, record: JsonDict) -> str`, which atomically writes and returns SHA-256. Readers reject unsupported schema versions. IDs/hashes use lowercase SHA-256; revisions use actual immutable upstream identifiers. NumPy `Words` means `NDArray[np.uint16]`, always original bit patterns, never numeric BF16 values; `QWords` means `NDArray[np.uint32]`.

Task 2 defines `NativePage(q: QWords, scales: Words, biases: Words, valid_count: int, abi_id: str, identity: str)` in `native.py` for bounded CPU exports and `NativeKV(keys: tuple[mx.array, mx.array, mx.array], values: tuple[mx.array, mx.array, mx.array], valid_tokens: int, capacity_tokens: int, abi_id: str)` for live native state. Import MLX lazily or under type checking so CPU codecs import offline. Page q stays packed; bounded scalar extraction is permitted, full-tensor expanded Q retention is not.

Task 3 defines `ModelHandle(model: Any, tokenizer: Any, identity: JsonDict)` wrapping the one loaded model. Task 4 defines `PromptRecord` as the validated JSON prompt record from spec section 10. Task 8 defines `RoundDecision`; Task 9 defines the raw `Session`; Task 13 extends that same session to shared providers. Do not invent parallel token conventions or alternate cache owners in later tasks.

### Command conventions to implement incrementally

Every command accepts `--out` for its result directory/file and saves errors before returning nonzero. Exit codes: 0 completed eligible experiment, 2 invalid input/format, 3 decisive gate stop, 4 missing prerequisite/unsupported environment. `report` succeeds when it accurately renders a negative result. `--help` and default pytest do not download or benchmark. Gate checks occur before model allocation or launching dependent kernels. After the Task 1 bootstrap, all `python`/`pytest` commands assume the ARM-native `.venv` is activated; the observed system-default Python 3.14.6 is not this environment.

Future commands use `python -m kvrefine.cli`. `verify` accepts `--backend bf16|q4|raw-dual|palette-dual|palette-exact|refine`, `--manifest`, `--split`, `--tokens`, `--draft`, `--max-new-tokens`, `--verifier batched|tokenwise`, `--check`, and `--out`; unsupported combinations are errors. `bench` requires a frozen configuration and suite name. Plain `probe --tokens 512` selects exactly one development prompt/domain by manifest IDs. Larger/model tests are opt-in, e.g. `pytest --run-model -m model`; GPU tests use `--run-metal -m metal`.
